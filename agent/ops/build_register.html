Writing into a Google Sheet — one step away

Almost Script covers it meanwhile
Was
The Drive connector's update_file changes only the title and parent folder. No call sets a cell value, so the agent could compute an allocation and not write one cell of it.
Now
Google runs a hosted Sheets MCP server at sheetsmcp.googleapis.com/mcp/v1. It is added, authorised and live, and it carries update_values (write cells) and update_spreadsheet (batchUpdate — which is how a cell gets a green background). Because it is a hosted HTTPS endpoint rather than a local subprocess, it works from a normal chat.
Blocked on
One enrolment step. The first call returns:
Access to this tool requires that your Google Cloud project (454021123290) is enrolled in the Google Workspace Developer Preview Program.
Fix
Enrol the project at developers.google.com/workspace/preview. One caveat: that programme is aimed at Workspace accounts, and the project sits under a personal Gmail — so enrolment may not be open to it.
Keep
ops/allocate_callsheet.gs stays. "Developer Preview" means Google can change or withdraw it; Apps Script has been stable for a decade.

Getting call sheets to callers — solved and proven

Working
How
One workbook per caller, attached to a Gmail draft. Tested end to end: Kharen's 200 numbers, 8.5KB, opened cleanly with the leading zeros intact.
Why not work email
The work account is Microsoft (brendon@pacificlinkglobal.com) and it is connected — but none of the three Outlook write tools can attach a file. Gmail's draft call takes attachments up to 25MB.
Why not SharePoint
Considered and rejected. External sharing is either "anyone with the link" — the same wide-open problem as the Drive call sheets — or "specific people", which emails each caller a one-time passcode to enter before every open. Twenty callers, on phones, every shift.
Side benefit
Each caller receives only their own numbers. The shared 20-tab workbook exposed everyone's list to everyone.

Access can be granted but never removed

Blocked Script not yet run
Why
share_file grants a role and, by its own documentation, only ever raises an existing one. There is no revoke call in the connector at all.
Exposure
60+ files with "Callsheet" in the name are owned by the account. 03/06/2025 Callsheet Nats Rural Poll was checked directly and returns:
{"role": "writer", "type": "anyone"}
Meaning
Anyone with the link can edit it — a file of New Zealanders' names and phone numbers. Others belong to Curia and to staff, so they need asking rather than fixing.
Now
ops/revoke_callsheet_access.gs — audits first and changes nothing, then closes link-sharing and removes stale editors on a second run. Still to be run.

WhatsApp will not say who voted in a poll

Blocked Solved another way
Why
A poll arrives through the API as type: "poll_creation" carrying the question and options — and nothing else. There is no voter list on the object. This is WhatsApp, not the connector; no plan upgrade changes it.
Instead
Text replies are readable, and every reply already carries its sender. So the question goes out as an ordinary message and from_chat_replies reads the answers — 13 14 15, Sun Mon Tue, Mon-Thu, all week, Mon Tue Wed but not Wed, not available. Better than a poll: nobody types their own name, which is where the spelling mess was being created.
Better still
Standing patterns read from six months of audit history cover 4 of the 5 days without asking anyone anything. The weekly question shrinks to the days that come up short.
Ruled out
lharries/whatsapp-mcp — its own README warns it is subject to the lethal trifecta: private data, untrusted content from 90 group members, and the ability to send. It is also local-only, so it could not reach a chat session. The WhatsApp Business API is official and safe, but cannot do group chats and takes the number over from the normal app.
What protects us
Read-only, plus draft everything, send nothing. Untrusted text can reach the agent; nothing leaves without a person reading it. That setting is doing real security work and should stay.

WhatsApp connector: quota and a browser dependency

Needs a decision
Limit
Blueticks free allows 5 API requests per 6 hours. One week's roster cycle — post the ask, read replies, post six daily rosters — needs roughly 12–15.
Engine
It's a browser extension driving a linked WhatsApp Web session, so the browser has to be open. Only the Pro tier claims to work while you're offline.
Cheapest fix
Basic tier, with the Mac mini as the always-on browser. Worth asking their support whether Basic lifts the 5-per-6-hours API cap before paying for Standard.

A server on your Mac can't be reached from a cloud session

Architectural
Why
Claude Code on the web runs in a throwaway container. MCP servers reach it only through claude.ai's connector settings — never from something installed on the container's filesystem, and never from a process on your laptop. Anything with stdio transport is local-only.
Consequence
Work needing Sheets write access has to happen in Claude Desktop on the Mac mini, or the server has to be hosted somewhere with an HTTPS endpoint and added as a custom connector.
Also
A hosted third-party option was tried and Google refused it — "This app tried to access sensitive info in your Google Account". That's Google's unverified-app block on restricted scopes, and it was right to fire. Running your own OAuth client (Desktop app type, yourself as a test user) avoids it because you become the publisher, and your tokens never leave your machine.

Names that can't be matched safely

Needs you
Unmatched
Alexis, Kris Dolz and Nelle appear in the roster and match nobody in the WhatsApp group closely enough to tag. (Nelle may be Shanelle.)
Collisions
Two group members are both saved as Florence Bularon on different numbers; there are also two Jeans and two Karens. A name that could be two people is matched to neither — tagging the wrong one puts the wrong person on a shift.
In the audits
43 name pairs look like the same caller entered twice, which splits their history and flatters the half without the failures. Reported, never auto-merged.
Fix
Confirm each once; they're written to an alias file and never asked again.

No contact list yet

Blocking email delivery
Needed
One sheet: name, WhatsApp number, email. Headings don't matter — they're matched loosely — but the name should be spelled as it appears in the audit sheet.
Unlocks
Call sheets emailed as attachments instead of shared from Drive. That removes the access-revocation problem at the source: an attachment can't be left open to the world eighteen months later.

Sundays are genuinely short

Operational
Numbers
Standing patterns cover 4 callers on a Sunday against 10 needed. Monday to Thursday are all over-covered.
Caveat
Patterns come from audited shifts, not all shifts, so every rate is a floor rather than a measurement — Sunday may be under-audited as well as under-staffed. Worth checking before treating it as a staffing problem.
